## Concurrent event-store acceptance

The store intentionally fails lock acquisition after two seconds. Under twelve simultaneous durable writers, a busy response is backpressure, not an acknowledged write or evidence of corruption. The concurrency acceptance caller retries only that exact error within a forty-second overall fixture budget, using the same observation and timestamp. Validation, capacity and I/O errors still fail immediately; exhausted retry budgets fail. Each writer reports its outcome explicitly, all children are reaped, and the test requires all 72 exact records plus valid concurrent snapshots. The separate held-lock/publisher-lease negative test still requires timeout while another owner holds the lock.

This corrects the test's former assumption that every concurrent call succeeds immediately. Production event-store code, two-second lock acquisition deadline, file checks, fsync/atomic replacement and publisher lease are unchanged. Real callers still receive a failure if a write is rejected and must handle it explicitly; this test-only change does not add production retry or claim guaranteed delivery.

## Supported coordinator adapter and owned feedback

`scripts/admin_artist_handoff.py` consumes a bounded sanitized JSON envelope on stdin. It returns an existing activity-schema event only for a first observation or changed task/turn state, plus a private cursor. It calls no API, reads no session or asset files, writes no live store, and sends no worker message. Keep real snapshots and cursors outside Git/public assets. `scripts/test-artist-handoff.py` exercises it through the existing writer, collector and browser projection using isolated fixtures.

A sanitized `codex.read_thread` snapshot contains `schemaVersion: 1`, `source`, `readAt`, `thread` (`id`, `hostId`, `kind`, exact `title`, `status`, `updatedAt`) and exactly one latest `turns` item (`id`, `status`, `startedAt`, `completedAt`). Bind it to one explicit `threadId`, `hostId`, `roleId: role:video:asset-library` and assignment. Strip transcript/tool/reasoning text before passing it to the adapter. Effective model transport, process IDs, parent launches and heartbeat timestamps are never inferred. Unknown source states remain unknown.

The cursor binds that owner and role. Repeated identical state, metadata-only changes and delayed snapshots emit no new event. `lastCheckedAt` is observer polling time; `firstObservedAt` remains the original status-observation time. Thus an in-progress snapshot expires in the existing browser after 90 seconds even if the backend keeps receiving reports. This deliberately does not advertise continuous execution. A real lifecycle/heartbeat producer must supply its own event identity/time under a separately verified contract before that behavior can be broadened.

An optional feedback item contains `id`, `responsibility`, `workKind`, `text`, `artifact`, `version`, nonempty `acceptanceEvidence`, `nextAction`, `receivedAt` and `provenance`. Responsibilities include research, anatomy/histology/cell biology, asset/scene creation, visual QA and animation. Only the existing artist has a bound task in this adapter. Unassigned roles return `blocked_owner_not_connected`; they never become executions. Busy artists defer, stale or unknown owner state blocks. A fresh terminal owner snapshot can produce a proposed `send_message_to_thread` request for the same owner, without model overrides or a second writer. The caller must persist the owned intent and recheck owner state before sending, then save acceptance or uncertain-outcome receipts. An uncertain send must be reconciled before retry. Local queued intent is never labeled canonical queue admission or running work.

`workKind: create_environment` requires `scientificBrief`: `id`, `version`, matching `artifact`, `state: ready`, `sourceLinks`, `coverage`, `readyAt` and `provenance`. Coverage requires nonempty `tissueLayers`, `cellTypes`, `morphology`, `relativeScale`, `normalVsPathological`, `displayConventions`. Source references must be HTTP(S); this validator does not fetch references or certify scientific correctness. `refine_existing` preserves safe progress and requires reconciliation before acceptance. Scientific review is still owned work, not implied by a successful adapter validation.
