# Admin activity
The database role in public.admin_members is authoritative. A verified server session and an admin membership are required for /account/admin and /api/admin/activity. User metadata never grants access. Membership has no client write grants; snapshots are readable only through admin RLS. Private responses are not cached.
## Reporting
scripts/report-admin-activity.py only reads process summaries for shared external runner jobs and checks the public homepage response. It sends no commands, credentials from jobs, log contents, document contents, or source paths. It cannot launch/stop/resume work. Run it through the shared external-project-runner.py in Video scope; retain its private configuration outside Git with mode 0600. Configuration keys: device, token, url, key (publishable key). Never commit the private configuration.
The reporter updates every 20 seconds. The admin page polls every 10 seconds and considers reports offline after 90 seconds. A lost monitor connection is not evidence that work finished. Job disappearance does not imply successful completion. Jobs started without the shared runner and cloud build queues are not monitored. The local monitor survives this session while its process and mounted drive remain available; it does not install a login item or restart after a reboot.
## Publisher privilege
The owner explicitly approved a persistent status-only reporting endpoint on 2026-10-19. public.publish_nas_activity is intentionally executable by anon but requires a 384-bit private token. Only a SHA-256 hash is retained in nas_private.activity_publishers. It can upsert three constrained snapshot rows, cannot read user data, modify membership or control production. Its security-definer warning is expected and reviewed, not an unauthenticated write permission. Calls are limited to 64 KiB and 100 jobs per source. Revoke a device by setting enabled=false in nas_private.activity_publishers. No private token is returned to browsers.
## Current scope
Website/workspace group: homepage HTTP health and guarded jobs whose names indicate site/auth/SEO/admin work. Research/learning: guarded Learn and CVA jobs. Video/media: other guarded Video jobs. Classification is based on runner scope and job name, not speculative AI inference. Queues, agent conversation internals, task dependencies and scientific validation outcomes require explicit instrumentation before they can be displayed.

## Interactive tree
The tree uses reported parent IDs. The local collector supplies nearest observed tracked runner ancestry; standalone jobs remain roots. It does not invent an orchestrator. Optional model, task, status and cost fields are shown only if supplied. The localhost-only example route is removed before the production build. Pan, zoom, fit, inspect and collapse/expand controls do not control agents.
